# 관리자 작업 화면

## 승인된 방향

관리자는 한 번에 한 관리 목록을 탐색한다. 공통 메뉴는 회원·체험, 믹싱 작업, 음원 관리, 커스텀 믹싱으로 구분하고 기존 관리자 주소를 유지한다. 운영 화면의 설명은 “서비스 사용 현황과 티켓, 작업 상태를 확인하고 관리할 수 있어요.”다.

[승인 시안](references/copy-singer/admin-navigation-proposal.png)은 2026-10-29 코드 구조를 재구성한 비교 자료이며 인물·수치는 예시다. 시안의 새 설명 문구 대신 위의 기존 문구를 사용한다. 시안 자체를 실제 운영 수치나 실제 화면 캡처로 해석하지 않는다.

## 목록과 작업

- 상단 메뉴는 실제 경로/URL을 가진 navigation이며 현재 메뉴와 키보드 focus를 표시한다. 회원/체험은 기존 Tabs primitive를 재사용한다.
- 회원 수·회원 목록·티켓 조정은 정식 회원만 포함한다. 체험은 별도 목록에서 분석 상태·보관기한·결과를 저장한 회원을 확인한다. 체험 건수는 실명 방문자 수가 아니고 결과 저장은 가입 전환이 아니다.
- 검색·필터·페이지는 목록별로 유지한다. 선택하지 않은 목록의 표와 조정 폼을 함께 노출하지 않는다. 빈 목록은 검색 결과 없음과 데이터 없음이 구분되게 안내한다.
- 티켓 조정은 회원 행에서 Sheet로 열어 대상을 고정하고, 종류·정수 조정량·사유·예상 잔액을 확인한 뒤 적용한다. 닫기/열기만으로 저장하지 않는다. 실패 retry에서도 동일한 요청을 중복 적용하지 않는다.
- 믹싱 목록은 상태·오류 코드·시도·날짜를 제공하며 상세에서도 사용자 오디오와 저장소 URL을 노출하지 않는다.
- 음원 등록/분석/공개·스냅샷 가져오기/내보내기와 커스텀 믹싱의 기존 동작을 유지한다. 커스텀 믹싱은 폼 중심으로 제공한다.

## 시각·상태

기존 design-system.md의 neutral white canvas, semantic token, typography, 4px spacing, 공통 Header/Footer와 기존 Tabs/Sheet/Button을 사용한다. 목록의 loading·empty·오류와 pending을 표시하고 작은 화면은 주 비교값과 action을 남기며 페이지 자체의 가로 넘침을 만들지 않는다. 새로운 global token이나 별도 관리자 theme를 만들지 않는다.
