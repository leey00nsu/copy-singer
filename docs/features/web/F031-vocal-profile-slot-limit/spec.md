## 목적

보컬 프로필의 무제한 누적과 보컬 분석의 무제한 사용을 서로 다른 정책으로 관리한다.

1. **보컬 프로필 슬롯**은 현재 저장 가능한 사용자 `USER` 보컬 프로필 수를 제한한다. 삭제하면 슬롯이 다시 열린다.
2. **분석 티켓**은 새 보컬 분석 작업을 사용할 수 있는 횟수를 제어한다. 프로필을 삭제해도 티켓은 복구되지 않는다.
3. 기존 단일 티켓은 **믹싱 티켓**으로 명확히 분리하고, 종류 기반 티켓 지갑으로 확장한다.

프로필 최대 보유 수와 가입 시 지급량·기능별 티켓 비용은 서버 환경변수로 관리해 운영 정책을 코드 변경 없이 조정할 수 있게 한다.

## 사용자 스토리

### US-1: 프로필 슬롯과 분석 가능 횟수 이해

**As a** Copysinger 사용자
**I want** 보컬 프로필 보유 수와 분석 티켓 잔액을 분석 전에 확인할 수 있다.
**So that** 프로필을 정리해야 하는지, 분석을 몇 번 더 사용할 수 있는지 혼동하지 않는다.

**Acceptance Criteria:**

- [ ] 분석 화면은 `보컬 프로필 {used} / {limit}개`와 `분석 티켓 {balance}장`을 서버 데이터 기준으로 표시한다.
- [ ] 프로필 슬롯에 여유가 있고 분석 티켓이 충분하면 기존 녹음·업로드 분석을 사용할 수 있다.
- [ ] 슬롯만 가득 찬 경우 기존 프로필 삭제가 필요하다는 안내와 `보컬 프로필 관리` 경로를 제공한다.
- [ ] 분석 티켓이 부족한 경우 프로필을 삭제해도 분석 티켓이 복구되지 않는다는 의미가 오해 없이 전달된다.
- [ ] 슬롯과 티켓이 모두 부족하면 분석 티켓 부족을 우선 상태로 안내하고, 슬롯 현황도 함께 확인할 수 있다.

### US-2: 분석 티켓 사용과 실패 환불

**As a** Copysinger 사용자
**I want** 분석 작업이 접수될 때만 분석 티켓을 사용하고, 최종 분석 실패 시 사용한 티켓을 돌려받는다.
**So that** 제한 초과·잘못된 요청·시스템 실패 때문에 티켓을 부당하게 잃지 않는다.

**Acceptance Criteria:**

- [ ] 새 분석 작업이 정상 접수될 때 `VOCAL_ANALYSIS` 티켓 비용을 차감한다.
- [ ] 슬롯 초과, active analysis 충돌, 지원하지 않는 파일, 잘못된 요청은 job 접수 전에 거절되며 티켓을 차감하지 않는다.
- [ ] 접수된 분석이 최종 `FAILED`로 끝나면 해당 job의 분석 티켓 비용을 한 번만 환불한다.
- [ ] retry 중인 job은 추가 차감하거나 중간 환불하지 않는다.
- [ ] 성공한 프로필을 사용자가 나중에 삭제해도 분석 티켓은 복구되지 않는다.

### US-3: 분석 티켓과 믹싱 티켓 구분

**As a** Copysinger 사용자
**I want** 분석에 사용할 수 있는 티켓과 AI 믹싱에 사용할 수 있는 티켓을 따로 확인한다.
**So that** 한 기능을 사용했을 때 다른 기능의 사용 가능 횟수가 왜 줄었는지 혼동하지 않는다.

**Acceptance Criteria:**

- [ ] 사용자 티켓 지갑은 `VOCAL_ANALYSIS`와 `AI_MIXING` 종류별 잔액을 분리한다.
- [ ] 계정 메뉴와 계정 화면은 `분석 티켓`, `믹싱 티켓`을 구분해 표시한다.
- [ ] 티켓 변경 내역은 어떤 종류의 티켓이 지급·사용·환불·관리자 조정됐는지 식별할 수 있다.
- [ ] 관리자 티켓 조정은 티켓 종류를 선택해 수행한다.

### US-4: 기존 사용자 티켓 보존

**As a** 기존 사용자
**I want** 티켓 모델이 바뀌어도 기존에 가지고 있던 티켓을 잃지 않는다.
**So that** 기능 정책 변경 때문에 이미 지급받은 사용권이 사라지지 않는다.

**Acceptance Criteria:**

- [ ] 기존 `User.ticketBalance` 값은 마이그레이션 시 `AI_MIXING` 지갑 잔액으로 그대로 이전한다.
- [ ] 기존 티켓 원장 항목은 `AI_MIXING` 종류로 backfill한다.
- [ ] 기존 믹싱 job의 차감·환불 관계와 잔액 의미가 유지된다.
- [ ] 기존 사용자에게 분석 티켓 지갑이 처음 생성될 때 현재 서버 설정의 가입 분석 티켓 지급 정책을 한 번만 적용한다.

## 기능 요구사항

### FR-1: 종류 기반 티켓 지갑

티켓은 `TicketKind`로 구분한다.

- `VOCAL_ANALYSIS` → UI `분석 티켓`
- `AI_MIXING` → UI `믹싱 티켓`

사용자 잔액은 종류별 지갑 레코드로 관리하며 `(userId, kind)`당 하나의 잔액만 존재한다. 티켓 원장은 각 변경에 `kind`, `amount`, `balanceAfter`를 기록한다.

원장 이벤트 종류는 티켓 기능 종류와 분리해 `SIGNUP_GRANT`, `USAGE_DEBIT`, `USAGE_REFUND`, `ADMIN_ADJUSTMENT`처럼 일반화한다. 기존 `MIXING_DEBIT`와 `MIXING_REFUND` 데이터는 각각 `USAGE_DEBIT`, `USAGE_REFUND` + `AI_MIXING`으로 마이그레이션한다.

### FR-2: 환경변수 기반 정책

다음 값을 서버 환경변수로 관리한다.

- `VOCAL_PROFILE_MAX_USER_PROFILES` — 기본 `3`, 유효 범위 `1..1000`
- `SIGNUP_VOCAL_ANALYSIS_TICKET_GRANT` — 기본 `5`, 유효 범위 `0..1000`
- `SIGNUP_MIXING_TICKET_GRANT` — 기본 `1`, 유효 범위 `0..1000`
- `VOCAL_PROFILE_ANALYSIS_TICKET_COST` — 기본 `1`, 유효 범위 `0..1000`
- `MIXING_TICKET_COST` — 기존 설정 유지, 기본 `1`

서버는 기존 `integerEnv()` 정책을 사용한다. 미설정 시 기본값을 사용하고, 잘못된 값은 조용히 보정하지 않고 명시적으로 실패한다. 클라이언트는 환경변수를 직접 읽지 않고 서버 응답의 제한값·잔액만 사용한다.

### FR-3: 보컬 프로필 슬롯 제한

일반 사용자 소유 `VocalProfile` 중 `sourceType = USER`인 현재 레코드만 슬롯으로 계산한다. `SONG` 프로필, 실패한 analysis job, 삭제된 사용자 프로필은 포함하지 않는다.

`used >= limit`이면 새 분석을 차단한다. 기존에 limit보다 많은 프로필을 보유한 사용자의 데이터는 자동 삭제하지 않고 `used < limit`이 될 때까지 새 분석만 차단한다.

### FR-4: 분석 티켓 차감

새 analysis job은 다음 조건을 모두 통과한 경우에만 분석 티켓을 사용한다.

- 유효한 새 idempotency 요청
- active analysis 없음
- 프로필 슬롯 여유 있음
- 오디오 형식·크기 검증 통과
- 분석 티켓 잔액이 설정된 비용 이상

job과 티켓 차감은 DB 관점에서 같은 접수 단위로 연결되고, 외부 source asset 저장 후 DB 접수에 실패하면 asset을 정리한다. 동일 idempotency 요청 재시도는 같은 job/차감 결과를 재사용해 이중 차감하지 않는다.

분석 job은 접수 시 사용한 `ticketCost`와 refund 상태를 보존한다. 설정값이 이후 바뀌어도 기존 job의 환불액은 접수 당시 비용을 사용한다.

### FR-5: 분석 실패 환불

접수된 분석이 retry를 모두 소진하거나 비재시도 실패로 최종 `FAILED`가 되면 `VOCAL_ANALYSIS` 티켓을 `ticketCost`만큼 한 번 환불한다. 환불은 idempotent해야 하며 worker 재실행으로 중복 지급하지 않는다.

성공한 분석 결과를 사용자가 삭제하는 것은 티켓 환불 조건이 아니다.

### FR-6: 믹싱 티켓 의미 유지

기존 단일 티켓 잔액은 기능적으로 `AI_MIXING` 지갑으로 이전한다. AI 믹싱 접수·부족 오류·최종 실패 환불은 기존 동작을 유지하되 종류 기반 지갑 API를 사용한다.

### FR-7: API 계약

티켓 잔액 API와 계정 API는 종류별 지갑을 반환한다. 분석 job 목록 응답은 최소한 다음 상태를 함께 제공한다.

- profile quota: `used`, `limit`, `remaining`
- `VOCAL_ANALYSIS` ticket balance와 현재 분석 비용

최대 프로필 수 초과는 `PROFILE_LIMIT_REACHED`, 분석 티켓 부족은 공용 insufficient-ticket 오류에서 `VOCAL_ANALYSIS` 종류를 식별할 수 있어야 한다. 둘 다 단순 retry로 해결되지 않는다.

### FR-8: 분석 화면 UX

분석 입력 영역에서 다음 정보를 분리해 보여준다.

- `보컬 프로필 {used} / {limit}개`
- `분석 티켓 {balance}장`
- 분석 가능 상태에서는 `분석을 시작하면 분석 티켓 {cost}장을 사용해요.` 안내

상태 우선순위는 `분석 티켓 부족 > 프로필 슬롯 만석 > 정상`으로 한다. 슬롯 만석에서는 `/library?tab=profiles`의 `보컬 프로필 관리` action을 제공한다.

### FR-9: 계정·공통 UI·관리자 UX

- 계정 메뉴: 단일 `티켓 N개` 대신 `분석 N장 · 믹싱 N장`을 구분해 확인할 수 있게 한다.
- 계정 화면: 분석 티켓과 믹싱 티켓 잔액을 각각 표시하고 통합 변경 내역에 티켓 종류를 명시한다.
- 관리자 티켓 조정: 대상 사용자와 함께 `분석 티켓` 또는 `믹싱 티켓` 종류를 선택한다.
- 양수 관리자 조정 알림: 어떤 종류의 티켓이 추가됐는지 사용자에게 명시한다.

### FR-10: 기존 계약 유지

프로필 삭제 가능 조건, 믹싱 작업에 연결된 프로필 삭제 제한, 추천 생성, 사용자별 단조 증가 `profileNumber`, 사용자당 active analysis 1개 제한, 믹싱 job의 접수·환불 정책은 유지한다.

## 비기능 요구사항

- **원자성/경합**: 종류별 잔액 차감은 음수가 되지 않아야 하고 serializable transaction 및 idempotency로 이중 차감을 막는다.
- **비용**: 슬롯 초과와 명백한 티켓 부족은 분석 worker 실행 전에 차단한다.
- **확장성**: 새 유료/제한 기능은 `TicketKind` 추가를 기본 확장 경로로 삼고 사용자 테이블에 기능별 balance 컬럼을 계속 늘리지 않는다.
- **접근성**: 티켓 부족·슬롯 제한은 색이나 disabled state만으로 전달하지 않는다.
- **마이그레이션 안전성**: 기존 믹싱 티켓 잔액과 원장 이력을 보존하고 자동 데이터 삭제를 하지 않는다.
