# Feature Spec: 비로그인 보컬 분석 1회 체험

## 개요

- **기능 ID**: BX9ASBJG4D9Y
- **기능명**: guest-vocal-analysis-trial
- **대상 레포**: copy-singer-web
- **작성일**: 2026-10-29
- **상태**: Approved

- **승인**: 2026-10-29 사용자 `진행해줘`. 비로그인 UI와 기존 회원의 결과 저장 흐름을 확인한 뒤 진행을 승인했다.
- **범위 확장 승인**: 2026-10-29 추천 목록·곡별 상세를 체험에 포함하고 로그인·저장 후 선택 곡으로 복귀하는 제안에 사용자 `진행해줘`로 승인했다. 구현 최종 승인과 병합 승인은 별도다.

## 목적

2026-10-29 사용자 `대체로 A10만 추가할 수 있을까?` 요청을 후속 운영 수정 범위로 수용한다. 기본 합성의 L4 공급 부족에 대응해 A10만 대체 후보로 추가하며, 기존 구현의 최종 승인이나 병합 승인으로 해석하지 않는다.

Google 로그인 전에 실제 보컬 분석 결과를 확인할 수 있게 하여 첫 사용의 부담을 줄인다. 익명 방문자에게 최초 1회 분석을 제공하고, 하루 전체 체험 수량은 단일 웹 프로세스 메모리에서 10건으로 제한한다. 웹 서버 재시작에 따른 전체 한도 초기화는 허용한다.

## 사용자 스토리

### US-1: 로그인 없이 결과 확인

방문자는 별도 계정 입력 없이 녹음·업로드하고, 분석 진행 상태·완성된 보컬 프로필·관련 오디오를 확인할 수 있다.

**Acceptance Criteria:**

- [x] 랜딩의 음성 스캔 진입부터 결과 열람까지 Google 로그인을 강제하지 않는다.
- [x] 기존 최소 유효 음성 5초, 권장 녹음 약 10초, 최대 분석 60초, 25MB와 지원 포맷 및 품질 검증을 유지한다.
- [x] 새로고침·네트워크 재전송은 기존 작업을 복구하며 체험을 중복 소비하지 않는다.
- [x] 성공한 익명 방문자의 두 번째 분석은 Google 로그인으로 안내한다.

### US-2: 하루 체험 마감과 실패 안내

방문자는 체험 가능 여부를 제출 전에 확인하고, 마감·처리 중·실패 상태에서 가능한 다음 행동을 알 수 있다.

**Acceptance Criteria:**

- [x] Asia/Seoul 기준 하루 신규 익명 분석 접수는 기본 10건 이하이다.
- [x] 한도가 소진되면 `오늘의 무료 체험이 마감됐어요.` 안내와 Google 로그인 경로를 제공한다.
- [x] 정식 회원의 분석·믹싱 이용권과 기존 익명 결과 열람은 체험 마감에 영향받지 않는다.
- [x] 접수 전 실패는 예약을 해제하고, 접수된 job의 최종 실패는 개인 체험 기회만 복구한다.

### US-3: 결과를 계정에 저장

방문자는 결과를 확인한 다음 Google 로그인을 선택하여 해당 결과를 계정에 저장하고 추천·믹싱으로 이어갈 수 있다.

**Acceptance Criteria:**

- [x] 결과 화면에서 `로그인하고 결과 저장하기`를 제공하고 로그인 후 보컬 프로필을 다시 만들 필요가 없다.
- [x] 신규 Google 가입과 기존 계정 로그인 모두 본인의 결과·job·미디어를 한 번만 안전하게 이전한다.
- [x] 익명 세션으로 믹싱·티켓·회원 계정·관리자 기능을 호출해도 서버가 거부한다.
- [x] 익명 사용자 생성에는 가입 이용권과 회원 온보딩을 제공하지 않는다.

### US-4: 추천까지 체험하고 선택한 곡으로 이어가기

- [x] 로그인 없이 본인 프로필의 전체 추천 목록·추천 키·추천 이유·검색/필터/정렬과 곡별 상세를 확인한다.
- [x] 다른 방문자의 프로필·만료된 체험은 추천 화면·API 모두 거부한다.
- [x] 추천 열람은 외부 AI 호출·분석 총량 소비·티켓 차감·믹싱 job 생성을 발생시키지 않는다.
- [x] 체험 추천에서 로그인하고 AI 믹싱하기를 누르면 프로필 저장 후 선택한 곡 상세로 복귀한다.
- [x] 복귀 직후 자동 믹싱하지 않고 기존 비용 확인과 명시적 실행을 유지한다. 잘못된 복귀 경로는 저장한 프로필 상세로 대체한다.

## 기능 요구사항

### FR-1: 익명 소유권과 개인 최초 1회

- 체험 시작 동작에서 익명 방문자 식별과 안전한 세션을 만들고, 유효한 기존 익명 세션은 재사용한다. 단순 랜딩 열람만으로 임시 계정을 만들지 않는다.
- 사용자에게 별도 로그인 UI를 요구하지 않으며 모든 분석 작업·프로필·관련 오디오에 소유권 검증을 유지한다.
- 한 익명 소유자에게 활성 분석은 최대 1개이며 성공은 최초 1회만 허용한다. 성공 후 사용 이력은 결과 삭제·만료·웹 서버 재시작으로 초기화되지 않는다.
- terminal failure 전에는 추가 체험을 허용하지 않는다. 최종 실패 시 개인 권한을 복구하되 외부 job 중복 실행 방지와 worker 재시도 상한은 유지한다.
- 쿠키 삭제·다른 브라우저·다른 기기로 새 익명 방문자가 되는 우회 가능성을 수용한다. 실제 사람을 특정하는 지문 수집은 추가하지 않는다.

### FR-2: 프로세스 메모리의 일일 전체 한도

- `GUEST_ANALYSIS_DAILY_LIMIT` 기본값은 10, 0은 신규 체험 중지이다. 날짜는 서버 OS 시간대와 관계없이 Asia/Seoul을 사용한다.
- 한도는 익명 체험에만 적용한다. 정식 회원은 기존 분석 이용권 정책을 유지한다.
- body 업로드·외부 저장 전에 가능한 한도·개인 권한 검사를 수행하고, 동시 제출은 수량 예약으로 한도 초과를 방지한다.
- job 영속 접수를 최종 건수로 센다. 접수 전 실패·동일 job 재전송으로 인한 추가 예약은 해제하고, 접수 이후 실패에는 전체 건수를 반환하지 않는다.
- 날짜 변경·서버 재시작은 새 한도를 부여하며 이전 날짜의 예약 해제가 현재 날짜 카운터를 줄여서는 안 된다. 재시작 전 job은 복구하되 새 카운터에 재집계하지 않는다.
- 메모리 총량은 웹 제출 경로 한 곳에서만 관리한다. worker에 공유 메모리가 있다는 가정을 하지 않는다.
- 한도 거절은 stable reason code와 적절한 429 및 다음 한국 시간 자정 기준 재시도 정보를 제공한다. 메모리 상태를 조회할 수 없으면 신규 체험을 임의로 허용하지 않는다.

### FR-3: 회원 기능과의 경계

- 익명 허용 범위는 최초 분석 생성, 본인 job 진행 조회, 결과·관련 오디오 열람, 추천 목록·곡별 상세 열람, 체험 결과 삭제와 정식 로그인 연결이다.
- 추가 분석·AI 믹싱·티켓 원장과 조정·회원 라이브러리·알림·회원 온보딩·관리자 기능은 정식 회원 조건을 서버에서 확인한다.
- UI는 익명 사용자를 회원처럼 표시하거나 티켓 부족으로 체험을 차단하지 않는다. 회원 이용권 확인 모달은 실제 이용권 소비 동작에 유지한다.

### FR-4: 안전한 Google 로그인 전환

- 익명 세션 본인 증명을 기준으로 Google 인증이 끝난 계정에 결과·분석 job·원본 및 합성 reference 미디어를 함께 이전한다.
- 기존 계정의 보컬 프로필 번호·이용권 원장을 보존하며 반복 callback은 자료를 중복 생성하거나 혜택을 중복 지급하지 않는다.
- 진행 중인 job은 terminal 상태까지 기다린 뒤 이전한다. 이전 실패 시 익명 계정 삭제나 외부 미디어 삭제로 자료를 잃지 않는다.
- 성공한 이전은 회원의 기존 자료 보관·소유권·추천·믹싱 정책을 따른다.

### FR-5: 임시 자료 보관과 안내

- 계정으로 이전하지 않은 체험 결과와 관련 오디오는 terminal 상태 이후 24시간만 열람 가능하다. 만료 시 조회를 차단하고 기존 재시도 가능한 정리 절차로 삭제한다.
- 전체 익명 사용자 삭제로 성공 체험 사용 기록까지 지우지 않는다. 최소 사용 이력과 재생 가능한 음성 자료의 수명을 구분한다.
- 체험 시작 전에 음성 사용 권한, 외부 처리와 임시 보관 안내 및 기존 약관·개인정보 경로를 제공한다.
- 회원 자료의 기존 보관 정책을 변경하지 않는다.

### FR-6: 비로그인 추천 열람과 로그인 복귀

본인 체험의 미만료 프로필에 한해 추천 목록·곡별 상세·추천 GET/POST를 허용한다. 기존 점수 계산·공개 카탈로그·검색/정렬/필터·근거·영상 표시를 재사용한다. profile ID를 안다는 이유만으로 다른 방문자의 결과를 공개하지 않는다. 하루 분석이 마감되어도 기존 결과의 추천을 볼 수 있다. 임시 결과 24시간과 동일한 만료를 적용하고 기존 rate limit을 유지한다.

체험 프로필과 추천 화면에 추천 열람·저장 진입을 제공하고, 믹싱 action은 정식 로그인 및 프로필 저장으로 연결한다. 선택한 곡의 상세 경로를 로그인 callback과 저장 단계에 보존한다. 저장 완료 뒤에는 해당 프로필의 추천 목록 또는 UUID 곡 상세만 복귀 경로로 허용하며 임의 외부·타인 프로필·재귀 경로는 거부한다. 추천 계산에 새 외부 호출·분석 접수·티켓 소비를 추가하지 않는다. 실제 믹싱 생성 API의 회원 인증·소유권·티켓 확인은 유지한다.

## 비기능 요구사항

- **합성 GPU 가용성**: 기본 설정은 L4 우선·A10 대체만 허용한다. 기존 SOULX_GPU 단일 지정은 유지하며 L4를 지정한 경우에도 A10 대체를 적용한다. 동시 컨테이너 수·접수 멱등성·티켓 계약은 유지한다. 실제 반영은 별도 승인한 Modal 재배포가 필요하다. 요구사항: PRD-NFR-GPU-FALLBACK.
- **보안**: 추측 가능한 job/profile ID만으로 결과를 공개하지 않는다. 익명 세션도 서버에서 소유권을 검증하며 정식 회원 전용 route의 권한을 넓히지 않는다.
- **동시성**: 마지막 체험 자리에 여러 요청이 도착해도 접수 총량은 한도 이하다. 중복 클릭·독립 idempotency key·다중 탭의 개인 체험 경쟁도 검증한다.
- **복구**: 기존 영속 job·lease·deadline·retry·미디어 정리 계약을 유지한다. 총량 카운터만 재시작 시 소실된다.
- **운영**: 단일 웹 프로세스 전제이며 다중 웹 프로세스·서버 사이의 일일 총량 일치는 보장하지 않는다. 기존 신뢰 프록시 IP 요청 제한을 활용하고 새 CAPTCHA 서비스 설정은 필수 조건으로 추가하지 않는다.
- **검증**: 인증·소유권·가입 혜택·회원 분석 회귀, 시간 경계·동시성·중복 접수·실패·계정 이전·자료 만료를 검증한다. 실제 유료 Modal 호출 없이 재현 가능한 fixture·adapter를 우선한다.

- 새 로그인 공급자, 결제, 신규 분석 모델, 디자인 시스템 재설계
