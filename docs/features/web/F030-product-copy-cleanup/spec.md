## 목적

프로젝트 내 사용자-facing 텍스트를 실제 구현과 대조해 정리한다. 행동 결정에 필요하지 않은 반복 설명과 내부 구현 세부는 삭제하거나 축약하고, 현재 제공 기능·상태·제약과 맞지 않는 문구는 실제 동작에 맞게 수정한다. 기능 동작 자체는 변경하지 않으며 제품 카피의 정확성, 간결성, 용어 일관성과 말투 일관성을 개선한다. 문장형 카피는 현재 제품에서 사용하는 자연스러운 `~요` 존댓말 톤을 기준으로 한다.

이번 Feature는 특히 최근 기능 추가와 UI 재설계 과정에서 누적된 설명성 문구, 구현 세부를 그대로 드러내는 문구, 과거 동작을 전제로 한 문구를 대상으로 한다.

## 사용자 스토리

### US-1: 필요한 정보만 빠르게 이해하기

**As a** Copysinger 사용자
**I want** 화면의 제목·설명·상태·오류 문구가 짧고 실제 동작과 일치하기를 원한다.
**So that** 불필요한 설명을 읽거나 잘못된 기대를 만들지 않고 다음 행동을 빠르게 판단할 수 있다.

**Acceptance Criteria:**

- [ ] 주요 공개/인증 제품 화면의 사용자-facing 텍스트를 감사하고 변경 필요 여부를 분류한다.
- [ ] 현재 구현과 불일치하는 설명은 실제 동작에 맞게 수정하거나, 필요하지 않으면 제거한다.
- [ ] 동일 정보가 제목·본문·보조 설명에서 반복되는 경우 핵심 정보만 남긴다.
- [ ] 내부 구현 세부, 개발자 관점의 용어, 과도하게 세밀한 처리 방식을 사용자에게 설명하는 문구는 사용자의 판단에 필요하지 않으면 제거하거나 일반화한다.
- [ ] 상태·오류·empty·disabled 안내는 원인 또는 다음 행동을 판단하는 데 필요한 정보만 유지한다.
- [ ] 같은 개념은 화면 전반에서 가능한 한 동일한 사용자 용어를 사용한다.
- [ ] 설명·상태·오류·empty state·toast 등 문장형 카피는 자연스러운 `~요` 존댓말 톤으로 통일한다. 버튼·메뉴·탭·badge·짧은 라벨은 억지로 `~요` 문장으로 바꾸지 않고 간결한 명사형/행동형 표현을 유지한다.
- [ ] 추상적인 홍보 문구, 근거 없는 과장, 상투적인 친절 표현, 불필요한 감탄·수식·반복처럼 AI 생성문 특유의 범용 표현을 제거하고, 해당 화면의 실제 상태·행동·제약에 직접 연결되는 구체적인 표현을 사용한다.
- [ ] 접근성용 `aria-label`, 법적 고지, 오류 복구에 필요한 정보처럼 기능적으로 필요한 텍스트는 단순 축약을 이유로 제거하지 않는다.
- [ ] 카피 수정으로 기존 기능 동작, 라우팅, API 계약, 데이터 모델은 변경하지 않는다.
- [ ] 카피 가독성을 위해 필요한 경우 헤드라인의 작은 화면 글자 크기와 한글 줄바꿈 규칙은 제한적으로 조정할 수 있다.
- [ ] 카탈로그 음원 수처럼 런타임에 달라지는 값은 고정 숫자로 제품 문구에 약속하지 않는다.

## 기능 요구사항

### FR-1: 사용자-facing 텍스트 감사

공개 랜딩/로그인과 인증 제품 화면에서 사용자가 직접 읽는 제목, 본문, 도움말, 상태, 오류, empty state, toast, CTA, badge, placeholder를 확인한다. Storybook 전용 fixture나 테스트 fixture는 실제 제품 카피와 연결되지 않는 한 감사 대상에서 제외한다.

### FR-2: 과도한 설명 축약 또는 삭제

다음 유형의 문구는 사용자의 행동 판단에 필요한 정보가 아니라면 축약하거나 제거한다.

- 제목 또는 UI 자체가 이미 전달하는 내용을 반복하는 보조 설명
- 서버 처리 방식, 캐시, 포인트 수, 자동 polling 등 내부 구현 세부
- 사용자가 확인할 수 없는 정밀한 처리 과정을 암시하는 문구
- 동일 의미가 연속된 UI 요소에서 반복되는 문구

### FR-3: 구현 불일치 정정

현재 라우트, 기능 제공 여부, 지원 포맷, 상태 전이, 자동 갱신, 믹싱/추천/분석 계약과 맞지 않는 문구는 실제 구현을 기준으로 정정한다. 구현이 불분명한 경우 문구를 추측해 새 약속을 만들지 않는다.

### FR-4: 용어 일관성

핵심 3단계 제품 용어는 `목소리 분석`, `노래 · 키 추천`, `AI 믹싱`으로 통일한다. `보컬 프로필`, `라이브러리`, `티켓` 등 보조 개념도 화면별로 불필요하게 다른 표현을 사용하지 않도록 정리한다. 결과지향적 마케팅 헤드라인에서는 `내 목소리로 완성`처럼 사용자가 얻는 경험을 말할 수 있지만, 단계명·섹션명은 위 용어를 우선한다.

### FR-5: 기능적 텍스트 보존

접근성 레이블, 법적 동의/정책 문구, 오류 복구에 필요한 지시, 파일 형식/길이처럼 입력 전에 알아야 하는 제약은 의미를 손상시키지 않는다. 제거보다는 필요한 정보의 위치와 길이를 정리하는 방향을 우선한다.

### FR-6: 제품 말투와 문장 품질

문장형 사용자 카피는 현재 제품의 `~요` 존댓말 톤을 일관되게 사용한다. 다만 버튼, 메뉴, 탭, badge, 필드 라벨처럼 본래 짧게 읽히는 UI 요소는 `~요`를 강제하지 않고 기존 정보 구조에 맞는 간결한 표현을 사용한다.

다음 유형의 표현은 특별한 근거가 없으면 사용하지 않는다.

- `더 나은 경험`, `완벽한`, `스마트하게`, `손쉽게`, `새로운 차원`처럼 제품 고유 정보 없이도 어느 서비스에나 붙일 수 있는 추상적·과장된 문구
- 사용자의 감정을 추측하거나 필요 이상으로 다독이는 상투적 표현
- 제목에서 이미 말한 내용을 문장만 바꿔 다시 설명하는 문구
- 실제 기능보다 더 지능적이거나 정밀한 판단을 하는 것처럼 보이게 하는 표현
- 감탄사, 불필요한 수식어, 긴 서론 때문에 핵심 상태나 다음 행동이 늦게 드러나는 문장

카피는 가능한 한 `현재 상태 → 필요한 정보 → 다음 행동` 중 해당 화면에 필요한 요소만 남기고, 실제 UI와 데이터로 확인 가능한 내용을 우선한다.

## 비기능 요구사항

- **성능**: 텍스트 변경만으로 신규 런타임 의존성, 네트워크 요청 또는 렌더링 비용을 추가하지 않는다.
- **보안**: 내부 오류 세부, 인프라 이름, 민감한 운영 정보를 새로 사용자-facing 문구에 노출하지 않는다.
- **접근성**: 시각적 중복 문구를 제거하더라도 컨트롤의 accessible name과 상태 전달은 유지한다.
- **회귀 방지**: 기존 카피 문자열을 직접 검증하는 테스트가 있다면 의도된 새 문구에 맞춰 갱신한다.

## 제외 범위

- 레이아웃, 색상, 타이포그래피, 컴포넌트 구조의 대규모 시각적 리디자인. 단, 카피 가독성을 위한 제한적인 반응형 글자 크기·줄바꿈 조정은 포함한다.
- 신규 기능 또는 신규 사용자 플로우 추가
- API 응답 메시지 계약의 대규모 재설계
- 관리자 전용 화면의 전문 용어를 일반 사용자 수준으로 단순화하는 작업. 단, 명백한 구현 불일치는 수정할 수 있다.
- 이용 약관/개인정보 처리방침의 법적 의미를 변경하는 편집
