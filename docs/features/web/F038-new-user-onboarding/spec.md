## 목적

신규 로그인 사용자에게 서비스 소개와 분석 티켓·믹싱 티켓 안내를 프로젝트 톤의 가벼운 모달로 제공하고, 확인 완료 상태를 영속화해 다시 노출하지 않는다.

신규 사용자는 로그인 직후 보컬 분석, 노래 추천, AI 믹싱의 관계와 가입 시 받은 두 티켓의 차이를 아직 알기 어렵다. 첫 인증 진입에서 기존 생성 퍼널과 같은 3단계 흐름으로 핵심 개념과 티켓 용도를 설명하고, 확인한 사실을 계정 단위로 저장해 이후 이용을 방해하지 않는다.

이 Feature의 대상은 배포 이후 새로 생성된 일반 사용자 계정이다. 배포 전에 존재한 사용자는 마이그레이션 시 온보딩 완료 상태로 이관해 새 안내를 소급 노출하지 않는다.

## 사용자 스토리

### US-1: 첫 로그인에서 서비스 흐름 이해

**As a** 새로 가입한 사용자
**I want** 첫 인증 화면에서 Copysinger가 무엇을 하는 서비스인지 짧게 안내받고
**So that** 다음 행동을 망설이지 않고 시작할 수 있다.

**Acceptance Criteria:**

- [ ] Google 로그인을 마친 신규 사용자가 처음 인증된 제품 화면에 진입하면 제품 shell 위에 온보딩 모달이 열린다.
- [ ] 온보딩은 기존 생성 퍼널의 stepper UI를 재사용한 3단계 모달이며 `목소리 분석 → 노래 추천 → AI 믹싱` 순서로 이동한다.
- [ ] 모달 좌측 상단은 기존 Copysinger 브랜드 마크를 사용하고 범용 장식 아이콘을 사용하지 않는다.
- [ ] 제목·본문·버튼은 기존 제품의 간결한 `~요` 존댓말과 실제 기능 용어를 사용하며 과장된 홍보 문구를 사용하지 않는다.
- [ ] 1·2단계는 `다음`, 2·3단계는 `이전`을 제공하고 마지막 단계의 명확한 완료 action `시작하기`로 온보딩을 끝내며 현재 진입한 제품 화면을 계속 이용한다.

### US-2: 분석 티켓과 믹싱 티켓 이해

**As a** 새로 가입한 사용자
**I want** 가입 시 받은 두 티켓이 어디에 쓰이는지 구분해 보고
**So that** 분석과 AI 믹싱을 시작할 때 예상하지 못한 티켓 사용을 피할 수 있다.

**Acceptance Criteria:**

- [ ] 1단계는 분석 티켓이 목소리를 분석해 보컬 프로필을 만들 때 사용된다고 설명한다.
- [ ] 2단계는 저장된 보컬 프로필을 기준으로 어울리는 노래와 키를 추천한다고 설명한다.
- [ ] 3단계는 믹싱 티켓이 추천 곡으로 AI 믹싱을 시작할 때 사용된다고 설명한다.
- [ ] 각 티켓의 현재 잔액은 서버 응답을 사용해 `분석 티켓 N장`, `믹싱 티켓 N장`으로 표시하며 가입 지급량을 클라이언트에 상수로 복제하지 않는다.
- [ ] 온보딩은 티켓 비용·차감·환불의 정본 계약을 바꾸지 않고, 실제 소모 action의 기존 확인 모달을 대체하지 않는다.

### US-3: 확인한 온보딩은 다시 보지 않기

**As a** 온보딩을 확인한 사용자
**I want** 이후 로그인이나 다른 기기에서 같은 안내를 다시 보지 않고
**So that** 반복 안내 없이 바로 서비스를 이용할 수 있다.

**Acceptance Criteria:**

- [ ] 1·2단계의 다음/이전 이동은 완료 상태를 저장하지 않고, 3단계의 `시작하기`를 선택하면 인증된 사용자 자신의 온보딩 완료 시각을 서버에 멱등적으로 저장한 뒤 모달을 닫는다.
- [ ] 완료 저장 중에는 중복 제출을 막고, 실패하면 오류와 다시 시도할 수 있는 완료 action을 유지하며 모달을 완료 처리하지 않는다.
- [ ] 완료된 사용자는 재로그인, 새 세션, 다른 기기와 어떤 인증 제품 경로에서도 온보딩을 다시 보지 않는다.
- [ ] 모달 데이터를 조회하거나 화면에 렌더링한 사실만으로 완료 상태를 저장하지 않는다.
- [ ] 배포 전에 존재한 사용자는 데이터 마이그레이션으로 완료 상태가 채워져 온보딩을 보지 않는다.

## 기능 요구사항

### FR-1: 서버 소유 온보딩 상태

`User`에 nullable 완료 시각을 저장한다. 기존 row는 마이그레이션 시점으로 backfill하고 이후 생성되는 신규 row는 미완료 상태를 유지한다. 온보딩 필요 여부는 localStorage·cookie·현재 브라우저가 아니라 인증된 사용자 row를 기준으로 판단한다.

개발 인증 bypass는 실제 신규 계정 온보딩 검증 대상이 아니므로 기본 제품 개발 흐름을 막지 않도록 완료 상태로 취급한다. 전용 Storybook 및 테스트 fixture에서 미완료 상태를 명시적으로 재현한다.

### FR-2: 인증 제품 shell에서의 노출

온보딩 gate는 인증된 제품 경로를 공통으로 감싸는 product layout/shell 경계에 위치한다. 공개 landing·login·legal 화면과 인증되지 않은 상태에서는 렌더링하지 않는다. 사용자가 로그인 전에 선택한 callback URL은 유지하며, 온보딩 완료 후 별도 강제 이동 없이 해당 화면을 계속 보여준다.

초기 서버 렌더링에서 완료 여부와 티켓 잔액을 함께 준비해 이미 완료한 사용자에게 모달이 잠깐 나타나는 현상을 피한다. 데이터 조회 실패 시 제품 화면 자체는 사용할 수 있게 하되 완료로 기록하거나 잘못된 `0장` 잔액을 표시하지 않는다.

### FR-3: 브랜드가 적용된 3단계 온보딩 모달

모달은 기존 공용 `Dialog`, `Button`, Copysinger `ProductMark`, 생성 퍼널의 stepper UI, spacing, typography와 semantic color token을 재사용한다. 상단에는 브랜드 마크와 소개 문구 다음으로 3단계 stepper를 배치한다.

1. `목소리 분석`: 마이크/음성 icon, 보컬 프로필 생성 설명, `분석 티켓 현재 N장`
2. `노래 추천`: 음악 icon, 보컬 프로필을 기준으로 노래·키를 추천한다는 설명
3. `AI 믹싱`: waveform icon, 추천 곡으로 결과를 만든다는 설명, `믹싱 티켓 현재 N장`

stepper는 현재 단계를 `data-accent`, 완료 단계를 foreground로 표시하는 기존 생성 퍼널 상태 규칙을 유지한다. 단계 본문의 음성·음악·waveform icon은 오디오·데이터 의미를 보조하는 단일 `data-accent` 계열로 제한하고 성공·주의·오류처럼 오해될 임의의 다색 배정을 하지 않는다. 새 이미지 asset, skip 링크와 자동 재생 motion은 추가하지 않는다. dialog title/description과 focus management를 제공하고 mobile viewport에서 stepper, 본문과 action이 잘리지 않아야 한다.

### FR-4: 멱등 완료 API

완료 mutation은 인증 세션을 요구하고 request body의 사용자 식별자를 신뢰하지 않는다. 서버는 세션 사용자 row의 완료 시각이 비어 있을 때만 기록하고 이미 완료된 요청에는 같은 성공 의미를 반환한다. mutation 성공 후 클라이언트 캐시와 열린 상태를 일치시킨다.

### FR-5: 기존 티켓 계약 재사용

온보딩은 `VOCAL_ANALYSIS`, `AI_MIXING` 지갑의 현재 서버 잔액과 기존 사용자-facing 명칭 `분석 티켓`, `믹싱 티켓`을 재사용한다. 가입 지급량, 작업별 비용, 실패 환불, 부족 상태와 티켓 소모 확인은 F031 및 기존 서버 계약을 유지하며 이 모달에서 별도 정책으로 정의하지 않는다.

## 범위 제외

- 선호 장르·목적 수집 설문과 개인화
- 온보딩 재열기 메뉴와 관리자별 강제 재노출 기능
- 튜토리얼 영상, coach mark, 샘플 오디오와 새 이미지 asset
- 티켓 지급량·비용·환불 정책 변경 또는 결제 기능
- 기존 가입자에게 새 온보딩을 소급 노출하는 캠페인

## 비기능 요구사항

- **성능**: 이미 인증 layout에서 수행하는 사용자 조회와 티켓 지급/잔액 흐름에 결합해 불필요한 client waterfall을 만들지 않는다. 완료 사용자에게는 온보딩 client UI를 열지 않는다.
- **보안**: 상태 조회와 완료 mutation은 서버 세션의 사용자 ID만 사용하고 다른 사용자 ID를 입력받지 않는다. 티켓 잔액과 온보딩 상태는 인증되지 않은 응답에 노출하지 않는다.
- **접근성**: 공용 dialog semantics, 접근 가능한 제목·설명, stepper의 `aria-current=step`, 초기 focus와 키보드 focus trap을 유지한다. 360px 폭에서도 horizontal overflow 없이 각 단계 설명과 이전·다음·`시작하기` action에 접근할 수 있어야 한다.
- **신뢰성**: 완료 mutation은 재시도와 중복 요청에 안전해야 하며 저장 실패를 성공으로 낙관 처리하지 않는다.
