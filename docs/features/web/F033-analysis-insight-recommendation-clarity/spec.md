## 목적

현재 Copysinger는 분석 내부 계약에서 필요한 기술 수치와 사용자가 실제로 이해하고 행동하는 데 필요한 정보를 같은 화면에 섞어 보여준다. `클리핑`, `평균 음량(RMS)`, `샘플레이트`, raw `MIDI`, `피치 안정성`은 분석 품질 검증·운영·내부 계산에는 의미가 있지만 성공한 보컬 프로필을 이해하는 핵심 정보로는 과도하거나 오해 가능성이 있다.

또한 현재 UI의 `실용 음역`은 실제로 이번 녹음에서 관찰된 p10–p90 구간이고 `전체 관측 음역`의 최저/최고도 raw 극값이 아니라 2·98 분위 경계다. 이를 실제 발성 능력이나 성종처럼 해석하지 않고 관찰 데이터에 맞는 용어로 바꾼다. `B3`, `D4` 같은 국제 음이름은 음악 이론에 익숙하지 않은 사용자도 이해할 수 있도록 한국어 계이름을 함께 제공한다.

추천 화면은 `adjustedScore`를 `추천 적합도`로 표시하면서 서버의 실제 ranking은 `selectionScore`로 계산해 `추천 적합도 높은 순`과 `종합 추천 순위`가 서로 다른 결과를 만들 수 있다. 이 Feature는 추천 scoring에서 모든 곡에 동일하게 더해지는 profile confidence 가산을 제거하고, 사용자-facing `추천 점수`, 표시 순위와 기본 정렬을 하나의 결정적 ranking 기준으로 통일한다.

## 조사 결과와 용어 기준

### 분석 데이터 의미

- `minMidi`, `maxMidi`: analyzer의 유효 pitch frame에서 2·98 분위 경계다. 실제 발성 가능한 절대 최저·최고음으로 표현하지 않는다.
- `p10Midi`, `p90Midi` 및 `tessituraLowMidi`, `tessituraHighMidi`: 현재 analyzer에서는 동일한 p10·p90 값이다. `실용 음역` 대신 **`주요 음역`**으로 표현한다.
- `medianMidi`: p50이며 **`중심 음`**으로 표현한다.
- `voicedRatio`: pYIN이 voiced로 판정하고 유효 F0를 얻은 frame 비율이다. 사용자-facing에서는 **`유효 음성 구간`**으로 표현하며 “전체 녹음 중 음높이를 추적할 수 있었던 구간”이라는 설명을 제공한다.
- `pitchStability`: 자유 가창에서는 멜로디 이동과 비브라토의 영향을 함께 받는 내부 지표이므로 성공한 프로필의 핵심 성능/실력 지표로 표시하지 않는다.
- `clippingRatio`, `rmsDb`, `sampleRate`: 입력 검증·품질 gate·운영 진단에는 계속 사용하지만 성공한 사용자 분석 결과의 핵심 카드에서는 숨긴다.
- raw MIDI 숫자: 내부 계산에는 유지하되 사용자-facing 본문/tooltip에서는 숨긴다.

### 음이름 표기

국제 음이름은 한국어 계이름과 함께 표시한다.

- `C4` → `도4(C4)`
- `D4` → `레4(D4)`
- `F♯4` → `파♯4(F♯4)`
- `B3` → `시3(B3)`

분석 화면 하단에는 짧은 용어 설명을 제공한다.

- `C=도 · D=레 · E=미 · F=파 · G=솔 · A=라 · B=시`
- 숫자는 옥타브 위치를 나타낸다.

### 해석 문장 원칙

`평균적인 남성의 목소리`, `테너`, `소프라노`, `이 장르에 적합`처럼 현재 한 소절 분석으로 검증할 수 없는 성별·성종·장르 추론은 하지 않는다.

대신 측정된 값만 정형화해 설명한다.

예:

- `이번 녹음에서는 시3(B3)–시4(B4) 구간의 음이 자주 관찰됐고, 레4(D4) 부근에 음이 많이 모였어요.`

## 사용자 스토리

### US-1: 분석 결과를 음악 지식 없이 이해한다

**As a** 보컬 분석 사용자
**I want** 분석 결과를 기술 수치보다 음악적으로 이해할 수 있는 용어로 보고 싶다
**So that** 내 녹음에서 어떤 음역이 관찰됐는지 바로 이해할 수 있다

**Acceptance Criteria:**

- [ ] `실용 음역`은 사용자-facing에서 `주요 음역`으로 변경된다.
- [ ] `중앙음`은 `중심 음`으로 통일한다.
- [ ] `유성 비율`은 `유효 음성 구간`으로 표시한다.
- [ ] 국제 음이름은 한국어 계이름과 함께 표시한다.
- [ ] raw MIDI 숫자는 성공한 사용자-facing 분석 본문과 tooltip에 표시하지 않는다.
- [ ] 클리핑·RMS·샘플레이트·피치 안정성은 성공한 프로필의 핵심 카드에서 제거된다.

### US-2: 분석 결과의 의미를 과장 없이 이해한다

**As a** 보컬 프로필 사용자
**I want** 이번 녹음에서 실제로 관찰된 범위와 그 의미만 알고 싶다
**So that** 한 소절 결과를 내 성별·성종·절대 발성 능력으로 오해하지 않는다

**Acceptance Criteria:**

- [ ] 관측 음역은 실제 analyzer의 2·98 분위 경계라는 의미에 맞게 표현된다.
- [ ] 주요 음역은 p10·p90 범위라는 의미에 맞게 표현된다.
- [ ] 요약 문장은 주요 음역과 중심 음을 설명하며 주요 음역 폭을 별도 문장으로 노출하지 않는다.
- [ ] 성별, 성종, 장르 적합도는 추정하지 않는다.
- [ ] 분석 용어 각주가 결과 화면에 제공된다.

### US-3: 보컬 프로필 목록에서 필요한 정보만 본다

**As a** 저장된 보컬 프로필이 여러 개인 사용자
**I want** 목록에서 프로필을 고르는 데 필요한 정보만 보고 싶다
**So that** 의미가 약한 지표 때문에 표가 복잡해지지 않는다

**Acceptance Criteria:**

- [ ] 보컬 프로필 목록의 `안정도` 컬럼을 제거한다.
- [ ] pending/failed 분석 job row도 동일한 컬럼 구조를 유지한다.
- [ ] 목록의 음역 표기는 `주요 음역` 의미와 계이름 표기 정책을 따른다.

### US-4: 곡과 내 목소리의 비교 근거를 이해한다

**As a** 추천 곡을 확인하는 사용자
**I want** 곡의 주요 음역과 내 주요 음역을 같은 기준으로 비교하고 싶다
**So that** 원키/추천 키 점수가 무엇을 의미하는지 이해할 수 있다

**Acceptance Criteria:**

- [ ] 곡 상세는 가능한 경우 곡의 `주요 음역`과 내 `주요 음역`을 동일한 음이름 표기로 보여준다.
- [ ] 곡 상세의 `내 음역`에도 `곡 보컬 음역`과 동일하게 `중심 음`을 표시한다.
- [ ] 곡 분석 내부의 clipping/RMS/sample-rate/pitch-stability는 사용자-facing 곡 상세에 노출하지 않는다.
- [ ] 원키 적합도와 추천 키 적합도는 음역 기반 점수임을 명확히 구분한다.

### US-5: 추천 순위와 추천 점수를 하나의 기준으로 이해한다

**As a** 추천 목록 사용자
**I want** 첫 번째 곡과 추천 점수가 같은 기준으로 정렬되기를 원한다
**So that** `추천 적합도`와 `종합 추천 순위` 중 어떤 것을 믿어야 하는지 고민하지 않는다

**Acceptance Criteria:**

- [ ] 사용자-facing `추천 점수`는 서버 ranking에 사용하는 `selectionScore`를 기준으로 한다.
- [ ] 기본 추천 목록 순위와 기본 정렬은 추천 점수 내림차순으로 동일하다.
- [ ] `추천 적합도 높은 순`과 `종합 추천 순위`를 동시에 제공하지 않는다.
- [ ] `원키 적합도 높은 순`과 `곡명 가나다순`은 보조 정렬로 유지할 수 있다.
- [ ] 추천 점수는 확률처럼 보이지 않도록 `%`가 아니라 `점` 단위의 0–100 척도로 표시한다.

### US-6: 추천 알고리즘이 입력 품질과 곡 적합도를 혼동하지 않는다

**As a** 추천 사용자
**I want** 녹음 품질 때문에 모든 곡의 적합도가 똑같이 낮아지거나 높아지지 않기를 원한다
**So that** 점수는 곡과 내 음역의 관계를 나타내고, 입력 품질은 별도 주의사항으로 이해할 수 있다

**Acceptance Criteria:**

- [ ] key-fit scoring에서 profile confidence가 모든 곡 후보 점수에 동일한 가산점으로 포함되지 않는다.
- [ ] 새로운 scoring version을 사용한다.
- [ ] profile confidence/low-confidence 판단은 별도 안내 신호로 유지한다.
- [ ] 추천 키 탐색은 `-6..+6` 정수 semitone 후보와 기존 결정적 tie-break를 유지한다.
- [ ] 곡-사용자 주요 음역의 대칭적 overlap, 주요 음역 초과 부담, 관측 극단음 초과 부담은 계속 반영한다.

## 기능 요구사항

### FR-1: 사용자-facing 분석 용어 정규화

다음 용어를 제품 전체에서 일관되게 사용한다.

| 내부/기존 용어 | 사용자-facing 용어 |
| --- | --- |
| tessitura / 실용 음역 | 주요 음역 |
| median / 중앙음 | 중심 음 |
| voiced ratio / 유성 비율 | 유효 음성 구간 |
| pitch stability | 성공 결과 핵심 UI에서 숨김 |
| clipping ratio | 성공 결과 핵심 UI에서 숨김 |
| RMS / 평균 음량 | 성공 결과 핵심 UI에서 숨김 |
| sample rate | 성공 결과 핵심 UI에서 숨김 |
| raw MIDI | 사용자-facing 본문에서 숨김 |

내부 DB, analyzer response, snapshot/export, validation contract는 이 Feature에서 삭제하지 않는다.

### FR-2: 음이름 presentation helper

기존 `midiToNoteName()` 계산은 유지하되 사용자-facing presentation을 위한 별도 helper를 제공한다. helper는 국제 음이름과 한국어 계이름을 결정적으로 조합하고 sharp 표기를 보존해야 한다.

차트 축처럼 공간이 제한된 영역은 기존 국제 음이름을 유지할 수 있으나 카드·요약·tooltip에는 한국어 계이름 병기를 우선한다. raw MIDI decimal은 tooltip에서도 제거한다.

### FR-3: 보컬 프로필 요약 단순화

보컬 프로필 요약의 핵심 지표는 다음으로 제한한다.

1. 관측 음역
2. 주요 음역
3. 중심 음
4. 유효 음성 구간

요약 문장에는 주요 음역과 중심 음만 사용하고, `약 N반음`, `약 N옥타브` 같은 음역 폭 설명은 표시하지 않는다. `피치 안정도`를 요약 카드에서 제거한다. 기술적 품질 문제가 분석을 통과한 후에도 사용자 행동을 요구하는 별도 상태가 있다면 숫자 대신 행동 가능한 안내 문장으로만 표시한다.

### FR-4: 녹음 정보/상세 분석 정리

기존 `분석 품질` 6개 카드에서 클리핑·평균 음량·샘플레이트·피치 안정성을 제거한다. `유효 음성 구간`과 `녹음 길이`만 사용자 이해에 필요한 범위에서 유지하거나 더 간결한 `녹음 정보` surface로 재구성한다.

Histogram, pitch trace, low/mid/high reference audio는 유지한다. `MIDI` decimal 표기는 제거한다.

### FR-5: 보컬 프로필 목록 컬럼 정리

`안정도` 컬럼을 제거하고 desktop grid를 다음 의미로 재배치한다.

- 프로필 이름
- 생성일
- 주요 음역
- AI 믹싱
- 상태

모바일의 sr-only label과 분석 job placeholder도 동일한 구조를 따른다.

### FR-6: 곡 분석 presentation

추천 곡 상세에서 `songProfile`이 존재하면 곡의 관측/주요 음역을 사용자 프로필과 같은 presentation 규칙으로 보여준다. 사용자에게 직접 도움이 되지 않는 곡 분석의 QA 수치는 노출하지 않는다.

관리자용 catalog 운영 화면의 원키 추정·신뢰도·분석 상태는 운영 정보이므로 이 Feature의 사용자-facing 제거 대상이 아니다.

### FR-7: key-fit scoring v3

새 scoring version을 사용한다.

- profile confidence 가산 5점을 candidate score에서 제거한다.
- score 총합은 다시 0–100을 사용하도록 나머지 가중치를 재정규화한다.
- 기본 방향은 symmetric major-range overlap을 가장 크게 반영하고, 주요 음역 초과와 관측 극단음 초과를 별도 penalty로 유지한다.
- profile confidence 계산 자체는 low-confidence warning에 계속 사용할 수 있다.
- `clippingRatio`는 프로필 유효성 contract에 남길 수 있지만 key-fit score에 직접 가산하지 않는다.

정확한 weight는 plan에서 기존 fixture와 edge case를 비교해 확정하고 ADR에 기록한다.

### FR-8: 단일 추천 점수

`selectionScore`를 사용자-facing `추천 점수`로 사용한다. 새 추천 점수는 원키에서 부르기 쉬운 정도, 추천 키 적용 후 적합도, 키 이동 부담을 함께 반영한 ranking score다.

- 목록의 점수 표시: `추천 점수 87점`
- 목록의 순위: `rank`와 추천 점수 내림차순이 일치
- 상세: `추천 점수`, `원키 적합도`, `{추천 키} 적합도`를 구분하고 `키 조정 변화`는 표시하지 않음
- `adjustedScore`는 `추천 키 적합도`이며 더 이상 목록의 `추천 점수`로 가장하지 않는다.

### FR-9: 추천 정렬 단순화와 URL 호환

사용자 선택 가능한 정렬은 다음을 기본으로 한다.

1. 추천 점수 높은 순
2. 원키 적합도 높은 순
3. 곡명 가나다순

기존 URL의 `sort=adjusted-score` 또는 `sort=rank`가 존재할 수 있으므로 parser는 안전하게 canonical 추천 점수 정렬로 normalize하거나 명시적으로 호환 처리해야 한다. 새 UI에서는 두 옵션을 동시에 노출하지 않는다.

### FR-10: 추천 설명 용어 정리

추천 이유의 `편안한 음역`, `실용 음역` 표현은 현재 데이터의 측정 범위를 넘지 않도록 `이번 녹음의 주요 음역`, `곡의 주요 음역` 등 관찰 기반 표현으로 변경한다.

추천 점수와 적합도는 경험적으로 보정된 성공 확률이 아니므로 UI에서 확률처럼 설명하지 않는다.

## 비기능 요구사항

- **결정성**: 동일한 사용자 profile, catalog revision, song analysis revision, scoring version 입력은 동일한 추천 점수·추천 키·순위를 반환해야 한다.
- **호환성**: analyzer/Prisma/snapshot의 기존 raw metric 필드를 삭제하지 않는다. scoring version 변경은 기존 mix snapshot과 구분되어야 한다.
- **접근성**: 음역 차트의 aria-label도 새 사용자-facing 용어를 사용하며 색상만으로 의미를 전달하지 않는다.
- **성능**: 100곡 scoring은 기존 CPU 목표를 유지하며 UI presentation 변경으로 추가 네트워크 요청을 만들지 않는다.
- **안전한 해석**: 성별·성종·의학적 상태·장르 적합도를 분석 결과로 추론하지 않는다.
- **회귀**: 추천 키 범위, catalog revision 검증, mixing handoff, 티켓, owner scope, low/mid/high reference 재생 계약을 변경하지 않는다.
